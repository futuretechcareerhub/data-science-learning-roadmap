Time Series Forecasting: How to Predict Future Sales Using Python

A practical guide to forecasting time-dependent data, validating predictions and avoiding common modeling mistakes.

Published: September 26, 2026

Quick answer: Time series forecasting uses historical observations recorded over time to estimate future values. A reliable workflow starts by defining the forecast target and horizon, checking trend and seasonality, creating a simple baseline, splitting data chronologically, fitting suitable models, and evaluating forecasts on periods the model has not seen.

Unlike a typical random train-test split, time series validation must respect time order. Information from the future must not leak into training, feature engineering or model selection.

What Is Time Series Forecasting?

A time series is a sequence of observations indexed by time—for example, daily product sales, monthly revenue, hourly electricity demand or weekly website visits. Forecasting estimates future values using patterns in historical data and, where appropriate, known future information such as holidays or planned promotions.

Forecasts are estimates, not guarantees. Their usefulness depends on data quality, the stability of historical patterns, the forecast horizon and how the predictions will support a decision.

Understand the Main Time Series Patterns

Trend

A trend is a longer-term upward or downward movement. A growing customer base or a gradual decline in product demand may create a trend. Trends can change, so avoid assuming that a historical slope will continue indefinitely.

Seasonality

Seasonality is a recurring pattern at a known interval, such as weekday versus weekend sales or higher demand during an annual holiday period. The seasonal period must match the data frequency and business context.

Cycles and irregular variation

Cycles are longer-term fluctuations that may not have a fixed period. Irregular variation includes unexpected events, data errors and random noise. A model may not be able to forecast one-off shocks that have no useful leading indicators.

Autocorrelation and stationarity

Autocorrelation describes how observations relate to earlier observations. Stationarity, in a common time-series sense, means that key statistical properties such as mean and variance remain stable over time. Some classical methods work more naturally with stationary series; differencing or transformations may help, but should be chosen using training data and domain knowledge.

Start with a Clear Forecasting Problem

Before modeling, write down the target, time granularity, forecast horizon and business decision. For a retail example, the question could be: “What is the expected total daily unit sales for the next 14 days for each store?”

  • Target: units sold, revenue, demand or another explicitly defined measure.
  • Frequency: daily, weekly, monthly or hourly, based on the decision and data quality.
  • Horizon: how far into the future the prediction must extend.
  • Granularity: total business, store, product, region or a combination.
  • Constraints: stockouts, returns, promotions, holidays, store closures and missing dates.

Forecasting each product-store combination can behave very differently from forecasting an overall total. More granular series often have fewer observations and more zeros or irregular demand.

Prepare Time Series Data Correctly

Use a consistent timestamp, timezone and frequency. Sort observations chronologically and inspect duplicate timestamps, missing periods, outliers and changes in data collection.

  • Aggregate records to the chosen time grain using a documented business definition.
  • Distinguish a true zero from a missing or unreported observation.
  • Investigate stockouts: recorded sales may understate demand when an item was unavailable.
  • Account for returns, cancellations and business-calendar differences where relevant.
  • Keep an untouched final test period for the final performance estimate.

Do not automatically fill every missing date with zero. A missing row may mean no sales, a data pipeline failure or that the store was closed. Confirm the meaning before imputing values.

Build a Simple Baseline First

A baseline gives you a reference point that a more complex model must beat. Common choices include:

  • Naive forecast: use the last observed value for every future step.
  • Seasonal naive: use the value from the corresponding previous seasonal period, such as the same weekday last week.
  • Moving average: forecast from a recent window of observations.

For data with weekly seasonality, a seasonal naive forecast can be a surprisingly informative benchmark. If an advanced model cannot consistently outperform an appropriate baseline on a realistic holdout period, revisit the data, features and forecast objective.

Python Example: Create a Chronological Baseline

The following example assumes a DataFrame named df with columns date and sales, containing one row per day after appropriate aggregation. It uses the previous week's value as a forecast for the matching weekday. The example is intentionally simple and does not include promotions or holidays.

import pandas as pd
from sklearn.metrics import mean_absolute_error, mean_squared_error
import numpy as np

df["date"] = pd.to_datetime(df["date"])
df = df.sort_values("date").set_index("date")

# Confirm frequency and missing dates before using this step.
# For a daily series, create an explicit daily index.
daily = df["sales"].asfreq("D")

# Keep the final 28 days as a chronological test period.
train = daily.iloc[:-28]
test = daily.iloc[-28:]

# Seasonal-naive prediction: same weekday from the previous week.
pred = test.index.to_series().apply(
    lambda d: daily.loc[d - pd.Timedelta(days=7)]
)

mae = mean_absolute_error(test, pred)
rmse = np.sqrt(mean_squared_error(test, pred))

print("MAE:", mae)
print("RMSE:", rmse)

This code illustrates the split and a weekly seasonal baseline. In a production workflow, verify that every lagged value was available at the forecast origin, handle missing values explicitly, and avoid using the test period to choose model settings. For multi-step forecasting, construct predictions using only information available at the time each forecast would actually be made.

There is no universally best forecasting algorithm. A simpler model can be preferable when data is limited, patterns are stable or interpretability is important. Compare candidates on the same forecast horizon and validation design.

Feature Engineering Without Data Leakage

Time-based features can include day of week, month, public holidays and known events. Lag features can capture recent values, while rolling averages can summarize recent history.

series = daily.to_frame("sales")
series["lag_1"] = series["sales"].shift(1)
series["lag_7"] = series["sales"].shift(7)
series["rolling_mean_7"] = (
    series["sales"].shift(1).rolling(7).mean()
)

The shift before rolling is important: it ensures the rolling feature at a timestamp does not include that timestamp's target. For multi-step forecasts, future lag features must be generated in a way that reflects what will be known at each step. Never use actual future sales as input features when those values would not be available in deployment.

Known future calendar features, such as weekday or a scheduled holiday, may be available at forecast time. Realized future weather, actual future discounts or future inventory may not be known; use forecasts, planned values or scenario assumptions as appropriate and document them.

Evaluate Forecasts the Right Way

Use a validation design that mirrors the operational forecast. A single chronological holdout is a starting point. Rolling-origin or walk-forward validation can test performance across multiple forecast origins and changing conditions.

MetricWhat it measuresWatch out for
MAEAverage absolute error in the target's unitsDoes not emphasize large errors as strongly as squared-error metrics.
RMSESquare root of average squared errorPenalizes larger errors more heavily and is sensitive to outliers.
MAPEAverage absolute percentage errorUndefined or unstable when actual values are zero or near zero.
WAPETotal absolute error divided by total absolute actual valueCan hide poor performance on small segments and is not meaningful if the denominator is zero.

Always report the metric with the evaluation period, horizon, aggregation level and baseline comparison. Consider evaluating important segments separately so that strong performance on high-volume items does not hide failures elsewhere.

Prediction Intervals and Uncertainty

A point forecast gives one estimated value. A prediction interval communicates a range that reflects forecast uncertainty under the model's assumptions. Intervals generally widen farther into the future, and actual coverage should be checked on held-out data.

For inventory or staffing decisions, the cost of underforecasting may differ from the cost of overforecasting. Consider decision-specific loss and uncertainty rather than choosing a model solely by average error.

Common Time Series Forecasting Mistakes

  • Randomly shuffling observations into training and test sets.
  • Using future target values in lag or rolling features.
  • Filling missing dates with zero without understanding why they are missing.
  • Ignoring holidays, stockouts, promotions or changes in the business process.
  • Comparing models on different horizons or inconsistent periods.
  • Using MAPE without checking for zeros or near-zero actuals.
  • Assuming historical patterns will continue through structural changes.
  • Reporting a forecast without its assumptions, limitations or baseline.

Frequently Asked Questions

What is time series forecasting used for?

It is used to estimate future values such as sales, demand, traffic, energy use and operational workload to support planning and resource decisions.

Which Python libraries are useful?

Pandas and NumPy help prepare data, Matplotlib supports visualization, and statsmodels and scikit-learn provide useful statistical and machine learning tools. Choose libraries based on the modeling task and validate results independently.

Is ARIMA always the best forecasting model?

No. ARIMA is one classical approach. Seasonal naive, exponential smoothing, regression and machine learning methods may be suitable depending on the data, forecast horizon and available predictors.

Why should time series data not be randomly split?

Random splitting can let information from later dates influence training while evaluating earlier dates, creating an unrealistic estimate. Chronological validation better represents forecasting future observations from past data.

What is the difference between MAE and RMSE?

MAE averages absolute errors in the target's units. RMSE squares errors before averaging and taking the square root, so larger errors have more influence.

Can time series forecasting predict unexpected events?

Not reliably when an event has no information available beforehand. External drivers, scenario planning and uncertainty ranges can help, but one-off shocks remain difficult to predict.
